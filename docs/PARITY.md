# HabitKit feature and verification status

The requested target is a 1:1 match to HabitKit on iOS 27. This matrix separates implemented code from parity that still requires device/reference evidence. The reference app's source code and private data format are unavailable; public documentation is collected in `research/habitkit/`.

| Feature area | Implemented | Remaining parity or native checks |
|---|---|---|
| Offline setup | No account; onboarding; optional clearly labeled sample habits | Compare first-run copy and flow |
| Habit editor | Name, description, 1,866 Lucide outline icons plus 1,407 Font Awesome icons and emoji, 21 colors, build/quit, tracking, cadence, categories, up to 3 reminders | Matches the reference New Habit sheet (icon cloud, captions, palette ring, Build A Habit / Quit A Habit, TRACKING shown directly, floating Save disabled until named); searchable catalog and full-grapheme custom emoji. Beyond the reference, the icon follows the name as it is typed, with suggested icons under the Name field |
| Yes/no / counts / measures | One-tap toggle, increment, total editor, exact 3 decimals, over-goal values, past-date correction | Compare keyboard and editor presentation |
| Historical goals | Dated target/mode/tracking rules; edits effective today | Reference conversion carry-over / alternative clear-history policies are not reproduced |
| Streaks | Daily / weekly / monthly; no goal; unfinished-today grace; current period reachability; new habits default to Daily and enabling Daily includes earlier no-goal check-ins (owner request) | Partial-period, target-edit and aggregate semantics are defined in ARCHITECTURE.md where docs are incomplete; the owner-requested daily-history behavior is not claimed as verified HabitKit parity |
| Quit | Clean days derived; slips; strict numeric threshold; historical mode meaning | Advanced conversion policies and locked clean-history carry-over need reference testing |
| Notes | Note-only, append/replace in Shortcuts, preserve on clear, setting hides without deleting | Dedicated newest-first notes list and calendar long press; compare interactions on device |
| Overview | Cards, Compact 1–7 recent days (set, along with name visibility and hidden habits, from the period pill's Compact List Settings sheet), three-column/adaptive Month, reorder/category filter, numeric progress rings, yesterday complete/clear commands, global and per-habit card appearance switches, filter/switcher/name/drag settings | Cards and Compact compared pixel by pixel with the owner's screenshots on a same-width simulator; new installs default to plain cards (no grid labels, streak or goal chips) like the reference |
| Grids/calendar | Civil dates, future/pre-start/paused states, partial fill, today outline, selected week start, month navigation | Full scrollable contribution history and months through habit creation; earlier months reachable for backfill, which moves the start date back; native geometry comparison pending |
| Month page layouts (owner extension, not HabitKit) | Top layout control on the third bottom page: original compact grid, full monthly calendars and twelve-month yearly cards per visible habit; saved choice, shared day editor and year statistics | Based on the owner's video; simulator results in VALIDATION.md, physical-device interaction and accessibility audit still required |
| Categories/archive | Multiple memberships, create/delete category, reorder habits, archive/restore, paused intervals, explicit delete | Editable category names and icons; native interaction comparison pending |
| Statistics | Habit/year selection, yearly grid, completions, rate, monthly area chart, current/best streak, completion-hour chart | Exact denominator/aggregate formulas need reference comparison; current formula documented |
| Habit sharing | PNG rendering, theme/color, description, streak, completion indicator; native system share actions verified by simulator UI test | Confirm exported image dimensions/content on device and precise reference layout; the system currently displays the PNG as a file |
| Year review | Multiple habit PNG with Cards / Compact / Grid / Poster formats | Format geometry is an approximation; exports with many habits need memory/device testing |
| Local reminders | Up to 3 per habit, weekdays/time, global check-in, permission denial, completion suppression, measurable 60-request queue | Native delivery, DST/travel/restart and many-habit queue test; reference background scheduling may differ |
| Dashboard and streak views (owner extension, not HabitKit) | Customizable widget board (13 designs in small, medium and large sizes, 4 styles, chosen habits or routine, titles and colors; touch and hold to change size or style or to duplicate, then move to drag it to a new place), Streaks and List overview layouts, Year History and shareable Year Calendar; matching home-screen widgets in the same sizes | Simulator captures of every design and size in both themes; UI tests check off and add a widget, configure and duplicate a quick check, drag a widget to a new place, and complete a routine from its widget; home-screen widget placement needs a device check |
| Explore pages (owner extension, not HabitKit) | Insights (weekdays, time of day, 12-month trend, habits that slip together), all-habits Calendar with a per-day check sheet, shareable Weekly Recap with an optional end-of-week reminder, searchable Notes timeline, Milestones (streak and check-in badges), Routines with Complete All, Challenges (7/14/30-day commitments built from selected habits and their existing check-ins), a countdown/stopwatch Timer with a Live Activity, and optional streak freezes | Simulator captures in both themes; UI tests complete a routine and log a timer both in the app and from the Live Activity's Finish button. Challenge editor/detail UI and full device interaction still need visual and device verification; Lock Screen, StandBy and Control Center placement need a device check |
| Widgets | Small/medium single habit and medium/large compact (3/8 habits, 10/11 days), plus the dashboard designs (Streak, This Month, 20 Weeks, Three Months, Today List, Today Ring, Goal Ring, Habit Stats, This Year, Next Badge, Quick Check, This Week, Routine) in their sizes; app intents and deep links | App Group signing, rapid tapping and midnight refresh need device test; single and multi-habit selection plus System / Light / Dark options; native widget placement pending |
| Shortcuts | Complete, clear, increment, log amount, log note, get progress, open habit, complete routine | Siri parameter discovery and execution need iOS 27 validation; progress is a JSON string rather than typed output fields |
| Recovery | 7 daily snapshots, 3 before-restore snapshots, manual versioned JSON export/import, corruption recovery | Mac/iPhone file picker, protection and app-kill behavior; HabitKit proprietary imports intentionally unsupported |
| Settings | Grouped APP / HELP / ABOUT list matching the reference; Theme page with System / Light / Dark (dark for new installs) and an accent color (default violet, the 21 habit colors or any custom color) and a Liquid Glass mode for the floating controls with System / Clear / Frosted transparency, a fine-tuning slider and an optional tint (owner extensions, not HabitKit; glass is off by default), first weekday, today outline, recent-day count, notes/haptics and card visibility switches | In-app language selection, What's New and the paid tier are not implemented |
| Pro / StoreKit | All implemented features currently available for development/testing | Reference free-4 limit, purchase paywall/subscriptions/lifetime/restore are not implemented; require your product IDs and commercial setup |
| Branding | HabitShelf name and its own app icon; bundled Figtree (OFL) and Lucide (ISC) like the reference, plus licensed Font Awesome icons for existing habits | Reference HabitKit branding/assets remain research-only |

The app has not been claimed as a verified complete 1:1 clone. To reach that bar, compile with Xcode 27, exercise the paired reference app, compare screenshots, and close the differences above. Core checks and build results are recorded in `docs/VALIDATION.md`.
